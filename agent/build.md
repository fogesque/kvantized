# Инструменты разработки

Документ задает обязательные требования к сборке. Любой PR в `develop` должен удовлетворять всем правилам ниже.

## BLD-01. Стандарт языка

* C++23
* Стандарт зафиксирован в `linter/.clang-format` (`Standard: c++23`); CMake-цели должны выставлять `CXX_STANDARD 23` и `CXX_STANDARD_REQUIRED ON`.

## BLD-02. Компиляторы и генераторы

| Платформа | Компилятор | Минимальная версия | Генератор |
| --- | --- | --- | --- |
| Linux | GCC | 14 (`gcc-14`, `g++-14`) | Ninja |
| Windows | MSVC | 17.x | Visual Studio 17 2022 |

Сборка другими компиляторами или генераторами в основных ветках не поддерживается.

## BLD-03. Система сборки

* CMake, минимальная версия — 3.25 (требование уровня `CMakePresets.json` v8).
* Файл пресетов — `vscode/CMakePresets.json`. Изменение названий пресетов запрещено без согласования с командой.
* Допустимые пресеты для конфигурации:
  * `amd64-linux-release`
  * `amd64-linux-debug`
  * `amd64-windows-release`
  * `amd64-windows-debug`
* Debug-пресеты включают `BUILD_SAMPLES=ON` и vcpkg feature `samples`. Release-пресеты собираются без сэмплов.

## BLD-04. Менеджер пакетов

* vcpkg в manifest mode. Корневой манифест — `vcpkg/vcpkg.json`.
* Переменная окружения `VCPKG_ROOT` обязательна; без неё пресеты не конфигурируются.
* Добавление зависимости — только через `vcpkg.json` с указанием версии или baseline. Установка пакетов в classic mode (`vcpkg install <pkg>`) запрещена.
* Хост-зависимости (`vcpkg-cmake`, `vcpkg-cmake-config`) объявляются с флагом `"host": true`.
* Опциональные зависимости выносятся в раздел `features`.

## BLD-05. Флаги компиляции

* В Release- и Debug-сборках предупреждения трактуются как ошибки:
  * GCC: `-Wall -Wextra -Wpedantic -Werror`;
  * MSVC: `/W4 /WX`.
* В Debug-сборках обязательно включены санитайзеры: `-fsanitize=address,undefined` (Linux). Отключение санитайзера в Debug допускается только на время локальной отладки и не должно попадать в коммит.
* Оптимизация в Release: `-O2` или `/O2`. Любое изменение уровня оптимизации в репозиторных файлах требует обоснования в PR.

## BLD-06. Форматирование и статический анализ

* Конфиг форматирования — `linter/.clang-format`. Конфиг проверок — `linter/.clang-tidy`.
* Перед открытием PR автор обязан:
  * прогнать `clang-format` по всем изменённым файлам;
  * прогнать `clang-tidy` хотя бы по Debug-пресету;
  * убедиться, что `clang-tidy` не выдаёт новых предупреждений в изменённых файлах.
* Глобальные `// NOLINT` без указания конкретного чека и причины запрещены. Корректная форма: `// NOLINT(<check-name>): <причина>`.

## BLD-07. Тесты

* Юнит-тесты используют GoogleTest, подключаемый через vcpkg-фичу.
* Тесты собираются в Debug-пресетах и должны проходить локально перед открытием PR.
* Падающие или временно отключенные тесты не сливаются в `develop`.

## BLD-08. Развертывание

* Артефакты упаковываются в Docker. Dockerfile и сопутствующие файлы лежат в каталоге `docker/`.
* Финальный образ собирается из Release-сборки через multi-stage build; build-окружение в финальном образе не остается.
* Тэги образов соответствуют версии из `vcpkg.json` поля `version`.

## BLD-09. Что должно проходить локально перед PR

В порядке выполнения:

1. `cmake --preset amd64-linux-debug`
2. `cmake --build --preset amd64-linux-debug`
3. `ctest --preset amd64-linux-debug` (или эквивалент проекта)
4. `clang-format` по изменениям
5. `clang-tidy` по изменённым файлам

Невыполнение любого пункта — повод закрыть PR без ревью согласно `pullrequest.md` PR-03.
